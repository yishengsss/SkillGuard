# 模型 Agent 审计

新版本常驻审计服务使用 OpenAI 兼容 Chat Completions 工具调用协议。CLI `auditor.cli` 的规则扫描与可选一致性检查保留原行为；网页和 `python -m auditor.agent` 启动的常驻服务必须配置模型，无配置不启动。

在项目 `.env` 设置 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`。地址必须 HTTPS（本机测试可 HTTP），模型必须返回 function tool calls。配置页公开模型名与配置是否齐全，不公开 API key 或服务地址。

流程：取得已登记的不可变快照 → 核对链上哈希 → 规则检查 → Agent 自主调用 `list_files`、`read_file`、`search_code` → 校验 `finish_audit` 报告 → 保存报告 → 按现有规则上链或等待人工裁决。工具只能读取此次快照，不执行代码、不访问项目私钥、不提供外部网络工具。模型不能直接决定链上状态，规则发现保留，严重级别由合并后的证据确定。

模型需读取参与登记哈希的全部文件和 manifest。每条 Agent 发现要求路径、行号、原文与解释；程序检查路径来自快照、原文与指定行对应。上限为 200 文件、256 KiB UTF-8 内容、16 轮、64 次工具调用、单次读取 400 行/32 KiB、总上下文 1 MiB。配置错误、模型拒绝、无工具调用、证据无效、未完整读取、超时或超限均为审计失败，禁止伪装为安全报告。

网页时间线显示真实请求轮次、请求 ID、工具名与读取范围。报告包含模型请求名、服务返回模型名、摘要、实际读取文件、轮次、调用数与用量。不会记录模型内部思考。历史报告原样保留并标为无 Agent 记录。

`tests/agent_api_fixture.py` 是明确标记的确定性协议测试服务，不是真实 AI。隔离 Anvil 测试使用它验证状态机和报告落盘；真实 API 验收独立执行，只读公开样例，不广播 BOT 交易。
