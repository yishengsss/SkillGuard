# SkillGuard 多页面与独立钱包规格

日期：2026-10-08。状态：设计稿，待用户审阅，尚未实现。

用户已确认：拆分角色页面；各角色使用自己的钱包；复用现有 Python 后端与 viem；支持自定义 ZIP 发布；展示真实 Agent 运行进度与报告。

## 1. 目标与范围

发布者可以提交自己的技能代码和 manifest，用当前钱包登记、支付押金并追踪审计。审计者运营方可以查看 Agent 实际处理过程、报告与回执，并完成质押和 SUSPICIOUS 裁决。管理员有独立入口，权限来自合约 owner。安装方可查看链上许可证和报告，使用现有 MCP 门禁。

本轮保持 contracts/src、规则、现有样本和报告哈希算法不变。后端继续运行在本机，默认绑定 127.0.0.1。以现有 BOT 配置读取真实历史；新增交易流程在隔离 Anvil 验收。本轮不增加 Git 拉取、公共托管、多审计者共识、沙箱执行或新的经济机制。

## 2. 页面与导航

所有页面采用共享导航、钱包状态、网络状态、消息样式和可访问的表单组件，支持窄屏和直接刷新 URL。

| 地址 | 页面 | 内容与动作 |
|---|---|---|
| / | 技能库 | 真实登记版本、按名称/版本/发布者筛选、状态、许可证、进入详情；无需连接钱包浏览 |
| /publish | 发布者 | 自定义 ZIP 上传、manifest/文件/哈希预览、登记、请求审计；按连接钱包查询我的发布及每个版本的后续状态 |
| /audit | 审计者运营 | 服务钱包与质押、Agent 心跳与游标、启动/停止、待审队列、运行事件、报告、失败原因和回执；连接匹配的钱包质押或裁决 |
| /admin | 管理员 | 当前部署与 owner、配置核验、钱包部署向导、仲裁；对非 owner 提供明确的只读状态 |
| /skills/<key> | 技能详情 | 发布者、版本、代码/metadata 哈希、来源包、链上状态、审计者、命中规则、报告、交易和许可证 |
| /install | 安装方 | 按实际技能版本检查门禁、查看允许/拒绝原因、调用服务端安装演示；提供真实 MCP 配置及调用说明 |

技能库不预填任何样本判定。已有样本作为普通链上条目出现。技能详情随 chainId、registry 和版本键定位，避免重新部署后显示另一组合约的任务。

## 3. 钱包身份与交易边界

### 3.1 人的操作

支持提供 EIP-1193 接口的浏览器 EOA 钱包。连接只请求地址；需要链上操作时，由钱包展示并签名交易。账户或网络变化后清除页面会话并重新核验。未检测到钱包时展示可读内容与明确的连接提示。

发布、请求审计、人工质押、SUSPICIOUS 裁决、部署和 slashAuditor 均使用当前连接钱包。网页 API 不使用 PRIVATE_KEY 或 OWNER_PRIVATE_KEY 代签这些动作。旧 CLI 保留作为本地工具，原网页代签端点退出默认路由，并返回迁移说明。

后端创建带 domain、URI、chainId、随机 nonce 和过期时间的 SIWE 登录消息。挑战有效期为 5 分钟，会话有效期为 30 分钟。校验原始消息、EOA 签名、来源、期限及一次性 nonce 后建立短期会话。钱包地址从验证结果取得。会话使用 HttpOnly、SameSite=Strict 的主机 Cookie，并继续验证独立 CSRF token；本机 HTTP 不标记 Secure，未来 HTTPS 托管需启用。钱包会话绑定当前链与 registry；部署配置变更会使旧作用域的操作失效。

HTTP 保留 Host/Origin 校验及 CSRF 防护。角色权限由服务端和合约校验：

- 发布者：已验证钱包可上传自己的包；已登记版本以链上 publisher 为准，仅该地址可请求审计。
- 管理员：每次管理操作重新查询当前 registry.owner()；客户端传入的角色名不授予权限。
- 审计运营者：启动/停止管理中的 Agent，或准备其待裁决报告，需要连接到配置的审计服务钱包地址。
- 浏览与门禁检查：无需钱包私钥；安装演示说明目标位于运行服务的机器。

首次实现支持普通 EOA。智能合约钱包的 EIP-1271 会话验证和 WalletConnect 移动连接留作后续功能，不宣称已经支持。

### 3.2 自动审计

无人值守的 Agent 继续使用服务端 AUDITOR_PRIVATE_KEY 签名审计结论，其运营者拥有并配置这把服务钱包。页面展示该地址和实际质押；连接其他钱包时可浏览，不能管理这一个 Agent。私钥通过现有本机配置提供，网页没有输入、读取或传输私钥的接口。

Agent 不自动质押，不调用 LLM，不执行上传代码。运营者仍在质押与 SUSPICIOUS 裁决时作出决定。

## 4. 自定义技能发布

发布流程：连接钱包 → 上传 ZIP → 校验并预览 → 钱包登记 → 确认实际回执 → 钱包请求审计并支付链上 MIN_DEPOSIT → 查看审计结果。

ZIP 包包含一个根 manifest.json，或一个统一顶层目录中的 manifest.json。沿用当前 manifest 格式：name、package、version、tools；工具描述和 inputSchema 从包读取。上传入口额外要求 name 和 version 为非空安全路径片段，分别最多 128 和 64 个 UTF-8 字节，拒绝斜杠、反斜杠、控制字符及单独的 . 或 ..，便于复用现有安装目录命名。用户更改 manifest 或代码时需提交新包并重新计算哈希。

上传校验：压缩文件最多 10 MiB，解压总量最多 20 MiB，最多 512 个文件。拒绝路径穿越、绝对路径、反斜杠路径、符号链接、特殊文件、重复/大小写冲突路径、.env*、.git、加密或损坏归档及超限内容。限制同时依据归档声明与实际读取字节，避免 ZIP 炸弹。解压不执行任何文件；普通文件设为 0644，原有任一执行位的文件设为 0755，拒绝 setuid/setgid 等特殊位。使用现有安全快照与哈希函数计算 codeHash、metadataHash，保持 CLI/Agent/Gate 一致。

包进入服务器生成的来源目录，所有权绑定已验证钱包。预览返回真实 manifest、文件数量、代码/metadata 哈希、包 ID 和可供当前 Agent 读取的相对来源。上传包按内容保存为不可变来源，已登记版本的代码不会被后续上传覆盖。

未登记的上传预览仅所属钱包可读取；登记后技能详情提供经过校验的 manifest 和文件列表。来源引用由服务器生成且限定在包存储目录，不通过接口读取任意服务器路径。包按钱包和内容寻址，另一地址上传相同内容不会取得既有草稿的所有权。每次审计和安装仍重新验证源文件，发现磁盘修改则拒绝处理。

链上版本键仍为 name+version，全局唯一。重复登记时显示已有版本及其发布者，用户可以提交新版本。登记与请求审计分开显示成功、拒签、失败和待确认；登记成功而押金交易未完成时，可仅继续请求审计。

后端提供校验过的交易参数；客户端核对 chainId、合约、账户和金额后调用钱包。最终成功来自回执与链上状态。页面不得把钱包返回交易哈希直接当作已登记或已审计。

本轮代码来源仍是同一服务保存的本地包目录。远程 Git URL 不作为可取代码来源；不展示不存在的仓库地址。新发布流程没有三个固定样本的下拉框。

## 5. 可观察的审计 Agent

### 5.1 数据来源

新增结构化运行记录，保存在项目 .cache 下的 SQLite 数据库。CLI Agent 与网页管理的 Agent 使用同一记录接口。任务由 chainId+registry+版本键定位；运行轮次、事件时间、报告哈希和交易哈希单独保存。

每个事件在实际动作发生时记录。阶段包括：收到请求、解析来源、核对快照哈希、扫描开始、报告生成并保存、广播交易、回执确认、等待人工裁决、失败或跳过。页面显示阶段时间线，不用计时器推算百分比。

报告继续采用现有规范化 JSON 和落盘流程，报告文件是报告内容的权威来源，SQLite 只保存运行与索引。前端通过受控接口查看 findings（rule、stage、severity、file、evidence）、engineVersion、auditor、时间戳及 reportHash。显示为文本，防止上传内容成为 HTML 或脚本。待裁决报告显示本地哈希；只有实际链上确认后才标注与链上 reportHash 匹配。

链上已审计历史通过真实状态、事件、已保存报告恢复。旧任务缺少过程记录时显示“已有审计结果，未保存运行日志”；不生成历史开始时间、耗时或进度。

### 5.2 管理与状态

网页启动管理中的常驻 worker，后台轮询真实 AuditRequested 并复用当前 Agent 流程。心跳与 worker 锁用于区分未启动、运行中、停止中和离线。CLI 与网页 worker 不能同时处理同一服务钱包的同一作用域；CLI 管理的实例标明来源，网页不终止未知进程。

停止操作让当前正在广播/确认的任务完成后停止接新请求。重新部署后旧 worker 不向新配置继续广播，需由运营者重新启动当前作用域。

SAFE/MALICIOUS 的本地结果和链上确认分开显示。SUSPICIOUS 显示待人工裁决，链上状态仍为 AuditRequested。来源不可用、哈希不匹配、RPC 错误、交易失败均显示真实原因，保留失败游标重试语义。

人工裁决从已保存的 SUSPICIOUS 报告生成最终报告，保留原 findings 并记录运营者选择的结论。最终报告先持久化，再由匹配的审计钱包提交；确认接口核对发送者、报告哈希和链上状态。质押不足时页面显示实际缺额及质押入口，worker 不自行补足。

已广播但未确认的交易记录其哈希；重试先查询这笔交易，避免因超时重复提交。报告必须先保存再广播。日志和错误不包含密钥、会话签名或完整凭据。

活动接口读取本地记录；链上汇总按需刷新并展示读取时间，避免进度轮询反复扫描整条链。

## 6. 管理员与安装入口

管理员页以当前链上的 owner 验证权限。部署向导先展示网络、四笔交易的作用与估算费用，由该钱包依次创建两个冻结合约并接线。后端核验实际四份回执、发送者、链、创建/调用数据、预期合约字节码、owner、接线及 minter 权限，再原子切换部署文件。校验失败保留原配置。

部署激活需验证原配置版本，避免并发部署覆盖。再次部署会创建新合约的事实在该页明确展示。日常查看状态使用刷新。允许的操作网络限于本地 Anvil 31337 和 BOT Testnet 968。

安装页按实际登记版本找到可用来源，复用 gate.check_install 和 MCP install_skill。显示链上状态、哈希比对、拒绝原因及实际复制结果。服务端复制安装不等同于在浏览器所在机器执行或安装代码；MCP 使用说明清楚标注这一边界。

## 7. 接口与模块

接口按责任拆分，现有 RPC 与部署配置集中读取。HTTP 响应不暴露 .env 或私钥。

| 接口组 | 用途 |
|---|---|
| GET /api/config | 当前公开链配置、合约、owner、审计服务地址及钱包能力 |
| /api/auth/challenge、/verify、/logout | SIWE 一次性登录、验证与退出 |
| /api/packages | 钱包所有权绑定的 ZIP 上传与真实预览；不接受任意服务器路径 |
| GET /api/skills、/api/skills/<key> | 链上目录与详情、按实际 publisher 筛选 |
| /api/publisher/prepare、/confirm | 准备登记/请求审计参数，确认真实交易与状态 |
| /api/auditor/prepare、/confirm | 人工质押及 SUSPICIOUS 报告准备、回执确认 |
| /api/agent/status、/runs、/events | 心跳、运行、任务与结构化事件 |
| /api/agent/start、/stop | 经钱包权限校验后管理 worker |
| GET /api/reports/<hash> | 受控报告读取与哈希核对 |
| /api/admin/prepare、/confirm、/activate | 钱包部署材料及四笔回执激活；slashAuditor 参数准备与实际回执确认 |
| /api/install/check、/execute | 复用当前门禁与 MCP 安装语义 |

读取使用 GET；上传、身份验证、参数准备、确认、worker 管理与安装使用 POST。上传端点单独处理 ZIP 和 10 MiB 限制，其余 POST 保留小体积 JSON 限制与来源/CSRF 校验。安装执行沿用现有本机 CSRF 会话，限制来源为已登记且门禁通过的包，无需钱包签名。

保持 ops/server.py 为路由与服务入口，将钱包会话、包存储、链查询、Agent 管理拆成独立模块。auditor 增加记录接口，不复制或改写判定规则。web 使用共享 CSS/JS、钱包模块和各页脚本；资源由受控路径提供，不能读取项目根目录的任意文件。

## 8. 验收条件

1. 各角色 URL 可独立打开和刷新，窄屏可用，导航与状态一致。发布者页不出现部署/仲裁按钮，管理员页不混入发布表单。
2. 两个不同发布者的本地测试钱包可以分别提交全新名字的技能；“我的发布”和链上 publisher 与签名钱包匹配。任何样本名均不参与业务分支。
3. 浏览器钱包拒签、切换账户、错链、nonce 重放、过期签名、伪造角色和非 owner 管理请求被正确处理。网页 API 不可触发服务器代签发布者/管理员交易。
4. 合法 ZIP 到预览、登记、请求审计完整通过；恶意路径、符号链接、秘密文件、归档超限和发布后内容替换被拒绝。
5. 后台实际处理的 SAFE、MALICIOUS、SUSPICIOUS、来源失败和 RPC 失败均在页面可见；报告、报告哈希、交易与最终链上状态一致。自动审计不代为质押。
6. Agent 重启/停止、待确认交易及失败重试保留正确状态；已有 BOT 历史报告可查看，缺失日志明确标注。
7. 正常技能安装成功；未审计、恶意、篡改和错链技能安装被拒绝，并保留已有安装。
8. 新交易验收使用隔离 Anvil 和公开测试夹具，不使用或复制原 .env 私钥；原 BOT 部署不重建。回归运行 Python 与 Foundry 检查，并保存各页面的浏览器截图及实际结果。

## 9. 已知边界

仍是单审计服务、现有静态规则引擎和本机服务的 MVP。合约原有的单审计者定案、不可撤销许可证、质押不能退出及无审计费等限制保持并在相关说明中如实呈现。多页面和钱包登录不会扩大检测能力。

本次设计不包含公网部署；发布源码以 ZIP 上传到当前服务处理。安装方的强制平台钩子、远程 Git 拉取、智能合约钱包与多 Agent 托管另行设计。
